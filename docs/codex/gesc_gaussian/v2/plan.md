## Convergence detector

Add `convergence_metric_mode`: inherited/default `pde_mean_v1`, opt-in
`centroid_windows_v2`. Reuse the existing detector and selected algorithm-pose
stream, including the configured simulation delay relay; leave shared PDE
history unchanged for its existing consumers.

Compute time-weighted centroids `c_i` of consecutive non-overlapping windows
of duration `W`, using source timestamps and trapezoidal integration with
interpolated boundaries and no extrapolation. After six completed windows:

`S_i = sum(norm(c_j - c_(j-1)), j=i-4..i)`.

`S_i` is in metres. Candidate eligibility requires `S_i < epsilon` and every
represented trajectory position within the selected maximum radius of the
six-window time-weighted mean position. Preserve timestamp/frame validity.
This is an explicit implementation interpretation of five differences of means;
the scan did not uniquely specify the formula.

New mode has no PDE startup timer, exponential decay, extra crossing counter,
or additional dwell: six complete windows provide persistence. Initial
development `W=3.0 s` gives first eligibility after 18 seconds of valid data.
Reset on a new SEARCH epoch, backward time, frame change, invalid position,
or excessive source-data gap. Duplicate timestamps add no time. One candidate
per SEARCH epoch; rejected verification begins a new SEARCH observation epoch.
Replace the inherited minimum-travel gate with confinement so tiny settled
motion remains detectable. Positional settling is a candidate, never proof of
a source, valid fill, or terminal goal.

Freeze and evaluate this finite 36-combination calibration grid on synthetic
traces and retained development trajectories:

| Parameter | Candidates |
| --- | --- |
| W (seconds) | 3, 6, 9 |
| epsilon (metres) | 0.03, 0.06, 0.12, 0.24 |
| maximum radius (metres) | 0.25, 0.50, 0.75 |

Require all declared positive detections and zero detections on declared
negatives. Negatives include center drift >=0.02 m/s and loops of radius >=1 m.
Among qualifying configurations minimize median detection delay; ties prefer
smaller radius, then smaller epsilon, then shorter W. Report effective drift
resolution without claiming rejection of arbitrarily slow drift. If none
qualifies, retain a failed calibration version before a separately documented
diagnostic amendment; never loosen its labels or silently replace its grid.

## Continuous GESC direction

Add `continuous_search_mode`: inherited/default `stationary_v1`, opt-in
`rolling_gesc_v2`. Extend existing filter/controller owners. Align cost,
encoder phase and base yaw by source time using the existing timekeeper
(relative experiment time and absolute ROS stamps must be reconciled).
Preserve existing body demodulation signal sign/gains. Rotate each sample
into world coordinates before averaging and return commands to the current
body frame:

`q_out_body = R(-yaw_now) * (0.5*q_instant_world + 0.5*q_mean_world)`.

The rolling mean covers one fully observed sensor revolution. The blend 0.5
is a development choice, not a proven optimum. Qualification uses actual
sensor world phase, including base yaw/mount geometry; all twelve 30-degree
sectors require >=2 observations. Three completed non-overlapping revolution
summaries must agree within 30 degrees. Reject near-zero vectors before
normalization: magnitude must exceed max(1e-6 in filter-output units, three
times measured cycle variability). Reuse the 50 ms synchronization tolerance.

Missing coverage/inconsistent means use fresh instantaneous GESC, never a
stationary sweep. Truly stale/nonfinite control inputs retain safety handling.
Clear augmented averaging on objective-weight/fill-revision/affine-direction
changes; do not reset merely on same-objective SEARCH/VERIFY/DESIGN transitions.
Apply the blend in SEARCH and moving VERIFY/DESIGN only. Preserve selected
Gaussian escape commands/geometric direction; do not feed raw attraction into
repulsion. Raw-source direction diagnostics are separate and optional.
Call this an averaged GESC improvement signal, not a proven spatial gradient:
the light sensor is position- and orientation-dependent.
